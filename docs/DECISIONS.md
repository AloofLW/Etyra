# 决策记录

## ADR-001：离线优先

状态：接受。v0.x 以本地 SQLite 为唯一事实来源，不把网络可用性作为核心学习流程前提；未来同步必须通过独立同步层加入。

## ADR-002：feature-first + 分层

状态：接受。按功能组织代码，再在功能内分 presentation/domain/data，减少跨功能耦合并明确三个 Codex 对话的所有权。

## ADR-003：Drift/SQLite

状态：接受。Drift 提供类型安全、迁移和测试支持；数据库实体不直接暴露给 UI。

## ADR-004：FSRS 不自创公式

状态：接受。v0.1 只预留可迁移字段和接口；v0.2 选择经过文档/测试验证的实现，并记录版本、参数、时区和复现结果。不得凭记忆重写公式。

## ADR-005：内容可信度优先

状态：接受。词源和构词关系必须有来源与校验状态；相似拼写不等于词源关系，无法确认时不作断言。

## ADR-006：当前工具链基线

状态：记录。已确认 Flutter 3.47.1 stable、Dart 3.13.1、Xcode 16.2；可用 iOS 模拟器为 iOS 17.5 和 18.3。最低部署版本由 ADR-010 定为 iOS 17.0；实际依赖版本和真机设备范围在工程初始化时复核并记录。

## ADR-007：共享契约冻结顺序

状态：进行中。前端与后端先冻结 v0.1 的领域模型、分页、错误和学习会话命令，再分别实现 presentation 与 data/database。路由注册、全局 provider 汇总和共享模型索引由一次只分配给一个对话的共享文件所有者维护。

## ADR-008：先确认产品目标，再进行工程规划

状态：接受。产品目标、核心用户、v0.1 学习闭环、非目标和成功标准必须先于工程初始化、功能拆分和依赖冻结。目标变化时，先更新 `docs/PRODUCT_GOAL.md`，再评估架构、数据模型和任务影响。

## ADR-009：v0.1 以学习闭环为功能边界

状态：接受。v0.1 优先完成“词根理解 → 关联单词 → 主动回忆 → 保存结果”的离线闭环；FSRS、通知、备份、完整发音和复杂统计延后到 v0.2 或 v1.0。页面和设计不得承诺尚未实现的能力。

## ADR-010：最低平台与系统外观

状态：接受。最低 iOS 部署版本为 iOS 17.0；指定 iPhone 12 Pro（用户目标 iOS 17.6，2026-11-01 实际已配对设备为 17.6.1）作为 Xcode 真机验收设备，并覆盖 iOS 17.5/18.3 模拟器。首版支持并验收浅色与深色系统外观，采用语义化颜色并跟随系统设置。动态字体和 VoiceOver 纳入 v0.1 基础验收；v1.0 再做完整可访问性审计。

## ADR-011：依赖候选版本与 SQLite 原生支持

状态：接受并已锁定。2026-11-01 在 Flutter 3.47.1 / Dart 3.13.1 下解析 `flutter_riverpod 3.4.3`、`drift 2.35.3`、`drift_flutter 0.3.1`、`drift_dev 2.35.2`、`build_runner 2.17.1`，完整依赖树见 `pubspec.lock`。不直接添加 `sqlite3_flutter_libs`、`sqlcipher_flutter_libs` 或 `path_provider`。`drift_flutter` 会间接引入两个 EOL no-op 包以阻止旧构建脚本；按上游设计保留传递依赖即可。Drift 2.32.0 起原生 SQLite 由 sqlite3 3.x build hooks 提供。

## ADR-012：v0.1 内容来源记录

状态：接受。内容来源记录至少包含标题、发布者、版本/版次、URL/定位信息、许可名称/链接、署名文本和访问日期。每条词源、释义、例句和构词关系都须能追溯到来源；没有可用许可依据的内容不得直接复制或打包分发。

## ADR-013：Flutter 工程骨架初始化

状态：完成。2026-11-01 使用 Flutter 3.47.1 stable 初始化 iOS-only 空应用；创建阶段使用 `--no-pub`，随后按 ADR-011 解析依赖。Xcode 的 iOS Deployment Target 设置为 17.0。后续完成 Drift 代码生成、分析与测试；iOS Simulator 和 iPhoneOS 架构不签名构建通过。Bundle ID 暂为 `com.example.etyra`，部署真机前必须替换为用户确认的唯一标识。

## ADR-014：v0.1 首轮学习完成条件

状态：接受。对单个内容条目，首次提交 `recalled` 后其学习阶段变为 `learned`；`needsPractice` 只将 `new` 转为 `learning`，不会把 `learned` 降级；跳过不更改学习状态。Session 是否完成不影响条目阶段。`learned` 仅表示完成一次主动回忆，不表示长期掌握，也不产生到期时间或 FSRS 状态。

## ADR-015：学习会话关闭语义

状态：接受。处理最后一张卡片（答题或跳过）时自动将 Session 置为 `completed`；`finishSession` 仅重复读取已完成总结，对尚有卡片或已放弃 Session 返回 `Conflict`。`abandonSession` 对 active Session 记录放弃时刻且保留既有事件；重复放弃返回原总结并保留首次结束时间；已完成 Session 不可放弃。

## ADR-016：持久化未知枚举值

状态：接受。已知但可安全替代的值按共享契约降级：校验状态为 `unverified`，affix kind/component role 为 `unknown`。未知多态构词类型不映射成 root/affix，忽略该关系；未知学习阶段不覆盖原始数据库值并返回 `Unsupported`。未知命令/内容类型返回 `Unsupported`。不得为了兼容而猜测语义。

## ADR-017：首版内容包更新策略

状态：接受。v0.1 导入仅允许新增内容或复用完全相同内容；稳定 ID 已存在但内容有差异时返回 `Conflict`，不覆盖、删除词条或改变用户学习状态。待定义并验证显式内容修订策略后再开放更新。

## ADR-018：共享 App 入口与依赖装配所有权

状态：接受。项目管理对话（对话 01）是 `lib/main.dart`、`lib/app/**`、根 `ProviderScope`、全局路由注册和 application provider 装配的唯一 owner；后端对话提供可注入接口/实现，不修改共享 app 入口；前端对话只实现 presentation 并提交消费契约。首个入口仅挂载明确标注的本地 fixture 预览，使用系统外观的 Cupertino app；不把未持久化的学习 fake 作为正式保存能力。接入持久化前需完成 Drift 学习写入事务及测试。
