# Etyra 视觉与交互设计规划

## 设计方向

简洁、克制、偏原生 iOS；视觉重点放在词根结构和学习动作，不用复杂插画或游戏化装饰分散注意力。整体感受应是安静、清晰、可信赖。

## 设计层级

### 颜色

- 主色：用于主要 CTA、选中状态和进度强调。
- 背景色：使用系统背景层级，支持浅色/深色模式的语义色。
- 正向色：完成、已掌握或成功反馈。
- 警示色：未验证来源、退出确认或需要注意的信息。
- 错误色：加载失败、输入错误和不可恢复操作。

实际色值在 Flutter 工程初始化后集中定义，不在页面中写死。

### 排版

- 使用系统字体和 Dynamic Type。
- 页面标题、区块标题、正文、辅助说明、标签建立明确层级。
- 单词和词根作为视觉主角，释义和来源作为次级信息。
- 不使用过小字体承载来源、错误或关键操作。

### 间距与组件

- 采用统一间距令牌、圆角和分组列表样式。
- 主要操作使用单一突出 CTA；次要操作使用文本按钮或导航动作。
- 学习卡片保持大面积可读内容和明确的操作区域。
- 组件优先使用 Cupertino 原生语义，必要时再创建自定义组件。

## 页面布局规划

### 学习首页

首页以产品名称、学习主张和单一主要学习动作为核心。演示阶段使用“开始学习演示”，明确说明内容未接入真实词库、记录不会保存；不展示虚构的学习进度或词库规模。“预览工具”作为次要入口，集中状态和故障注入。卡片随内容自然增高，在 iPhone 12 Pro 默认字体下保持清晰层级；放大字体时内容可滚动。

### 词根列表

使用紧凑分组列表；演示内容明确标记、来源待核验。真实数据接入后每项可展示词根形式、简短含义、关联单词数和可信度提示。搜索入口功能未实现时不提供不可用控件。

### 词根详情

顺序：词根主信息 → 含义/来源 → 构词关系 → 关联单词 → 开始学习 CTA。来源和未验证提示必须与对应内容相邻。

### 单词详情

顺序：单词和词性 → 释义 → 构词拆解 → 例句 → 关联词根/词缀 → 学习入口。发音按钮未接入时显示禁用或隐藏，不制造假反馈。

### 学习卡片

采用单卡片聚焦布局：提示区、可选提示、显示答案、反馈操作、进度。提交后锁定当前操作，完成状态明确，再进入下一张。

### 学习总结

显示本次学习数量、完成数、跳过数和继续路径；提供“返回学习首页”“再学一组”“查看词根”等明确操作。

## 交互状态

- 首次加载：使用轻量占位，不闪烁大面积骨架。
- 空状态：说明为什么为空，并提供下一步或返回路径。
- 错误：说明可执行的重试动作，不显示底层异常文本。
- 重复操作：按钮提交后立即进入 disabled/loading，结果返回后恢复。
- 退出学习：使用 Cupertino 确认弹窗，明确已记录内容不会被删除。
- 未验证内容：使用中性、非恐吓式提示，避免把不确定信息设计成确定结论。

## 可访问性

- 支持 Dynamic Type 和 VoiceOver；图标按钮提供语义标签。
- 触控目标不小于 iOS 推荐的可操作尺寸。
- 颜色不是传达状态的唯一手段，同时使用文字、图标或布局。
- 遵守 Reduce Motion；动效只服务于状态变化和方向提示。

## 设计组件清单

首批组件：`EtyraScaffold`、`EtyraSectionHeader`、`RootListTile`、`WordListTile`、`SourceBadge`、`StateView`、`PrimaryActionButton`、`StudyCard`、`AnswerFeedback`、`SessionProgress`、`SessionSummaryCard`、`ConfirmExitDialog`。

组件先服务一个页面，再抽取为共享组件；不得为了抽象而提前建立庞大设计系统。

## 设计验收

- 用户在每个页面都能明确下一步动作。
- 学习卡片不会同时突出多个竞争操作。
- 重要内容在动态字体放大后仍可读且不被截断。
- 空、错、加载和未验证状态与正常状态同样经过设计。
- 视觉设计不承诺尚未实现的发音、FSRS 或通知能力。
