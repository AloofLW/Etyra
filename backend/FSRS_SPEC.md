# FSRS 规范

## v0.1

不实现或自行推导 FSRS 公式。`learning_states` 预留调度版本、到期时间、稳定性/难度或序列化状态的兼容位置，但 UI 只依赖通用的“下一次复习时间/状态”概念。v0.1 的学习结果可记录为历史事件，不得伪装成 FSRS 调度结果。

## v0.2

选用有明确来源、许可证、版本、测试和参数说明的实现；在适配层封装，不让 UI 或 Repository 依赖第三方类型。验证内容至少包括：初始卡片、各评分输入、重复提交、跨日期/时区、应用重启、迁移和旧状态兼容。保存实现版本、参数版本和输入/输出快照以便复现。

任何公式、参数默认值、评分映射和时区规则都必须引用所选实现的官方文档或源码测试；没有验证前不得写入产品逻辑。

## 备份兼容要求（v0.2）

- 进度备份应保存每条复习记录及其所用调度实现/参数版本；如需保存当前调度快照，也必须携带版本标识。
- 恢复时不得用当前 FSRS 版本重新解释或重算旧记录，除非存在有来源、可复现并经过迁移测试的显式转换器。
- 遇到未知 FSRS 实现/参数版本时，可保留原始版本化数据供升级或导出，但不可静默改写；是否允许部分恢复由 ET-09 契约冻结时决定。
- 词库包更新不得修改 FSRS 状态、到期时间或复习历史。
